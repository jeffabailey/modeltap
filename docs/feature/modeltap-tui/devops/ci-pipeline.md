# CI Pipeline Design — modeltap-tui

**Platform:** GitHub Actions (per ADR-010)
**Branching strategy:** GitHub Flow (single main, PR-mediated)
**Trigger model:** PR + push to main + tag-push (`v*`) for releases

## 1. Workflow Files

```
.github/
├── workflows/
│   ├── ci.yml              # PR + push to main: fmt, clippy, build, test, deny, k3-bench, arch-rule
│   ├── release.yml         # Tag push: cargo-dist generates this, do not hand-edit
│   └── nightly.yml         # Optional: scheduled cargo-audit + cargo-outdated check
├── CODEOWNERS
└── PULL_REQUEST_TEMPLATE.md
```

`release.yml` is generated by `cargo-dist init` and regenerated by `cargo-dist generate`. It should not be edited by hand; configure via `[workspace.metadata.dist]` in `Cargo.toml`. See `release-strategy.md`.

## 2. CI Workflow Skeleton (`.github/workflows/ci.yml`)

```yaml
name: ci

on:
  pull_request:
    branches: [main]
  push:
    branches: [main]

concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true

env:
  CARGO_TERM_COLOR: always
  RUSTFLAGS: "-D warnings"
  RUST_BACKTRACE: 1

jobs:
  fmt:
    name: rustfmt
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
        with:
          components: rustfmt
      - run: cargo fmt --all -- --check

  clippy:
    name: clippy
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
        with:
          components: clippy
      - uses: Swatinem/rust-cache@v2
      - run: cargo clippy --workspace --all-targets -- -D warnings

  test:
    name: test (${{ matrix.os }})
    strategy:
      fail-fast: false
      matrix:
        os: [ubuntu-latest, macos-latest]
    runs-on: ${{ matrix.os }}
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
      - uses: Swatinem/rust-cache@v2
      - name: Build
        run: cargo build --workspace --all-targets --locked
      - name: Unit + integration tests
        run: cargo test --workspace --locked
      - name: Plugin contract tests
        run: cargo test --workspace --locked --test plugin_contract

  deny:
    name: cargo-deny
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: EmbarkStudios/cargo-deny-action@v2
        with:
          command: check

  arch-rule:
    name: architecture rule R1
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
      - uses: Swatinem/rust-cache@v2
      - run: cargo test --package modeltap-core --test architecture --locked

  k3-bench:
    name: K3 first-paint latency benchmark
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
      - uses: Swatinem/rust-cache@v2
      - name: Build release binary
        run: cargo build --release --package modeltap-app --locked
      - name: Run K3 benchmark against fixture inventory
        run: |
          # MODELTAP_HEADLESS=1 → app exits after first paint, prints timing JSON to stdout.
          # MODELTAP_FIXTURES=ci → use bundled fixture directory of ~50 models across 4 plugins.
          MODELTAP_HEADLESS=1 MODELTAP_FIXTURES=tests/fixtures/k3-bench \
            ./target/release/modeltap --emit-timing > timing.json
      - name: Assert K3 budget
        run: |
          set -e
          FIRST_PAINT_MS=$(jq -r '.first_paint_ms' timing.json)
          FULL_INV_MS=$(jq -r '.full_inventory_ms' timing.json)
          echo "first_paint_ms=$FIRST_PAINT_MS  full_inventory_ms=$FULL_INV_MS"
          # Hard fail: > 2 s first paint (per outcome-kpis.md K3 guardrail)
          if [ "$FIRST_PAINT_MS" -gt 2000 ]; then
            echo "::error::K3 regression: first paint ${FIRST_PAINT_MS}ms > 2000ms guardrail"
            exit 1
          fi
          # Soft warn: > 1 s first paint (target per architecture §7)
          if [ "$FIRST_PAINT_MS" -gt 1000 ]; then
            echo "::warning::K3 budget exceeded: first paint ${FIRST_PAINT_MS}ms > 1000ms target"
          fi
          # Hard fail: full inventory > 5 s (NFR margin over 3 s target)
          if [ "$FULL_INV_MS" -gt 5000 ]; then
            echo "::error::Full-inventory regression: ${FULL_INV_MS}ms > 5000ms"
            exit 1
          fi
      - name: Upload timing artifact
        uses: actions/upload-artifact@v4
        with:
          name: k3-timing-${{ github.sha }}
          path: timing.json
          retention-days: 30

  ci-success:
    name: ci success
    needs: [fmt, clippy, test, deny, arch-rule, k3-bench]
    runs-on: ubuntu-latest
    steps:
      - run: echo "All required checks passed."
```

The `ci-success` job is the single status check required by branch protection. It depends on all gates; one failure blocks the merge.

## 3. Quality Gates Catalog

| Gate | Stage | Type | Threshold | Failure mode |
|---|---|---|---|---|
| `cargo fmt --check` | Local pre-commit + CI fmt | Blocking | exact match | Block commit / merge |
| `cargo clippy -D warnings` | Local pre-commit + CI clippy | Blocking | zero warnings | Block commit / merge |
| `cargo test --workspace` | Local pre-push + CI test | Blocking | 100% pass | Block push / merge |
| Plugin contract tests | CI test | Blocking | 100% pass per plugin | Block merge |
| `cargo deny check` | CI deny | Blocking | no GPL deps; no advisories | Block merge |
| Architecture rule R1 | CI arch-rule | Blocking | core has no plugin deps; plugins do not depend on each other | Block merge |
| K3 benchmark first paint | CI k3-bench | Blocking (> 2 s) / Advisory (> 1 s) | < 1 s target, < 2 s guardrail | Block merge if > 2 s |
| K3 benchmark full inventory | CI k3-bench | Blocking | < 5 s on fixture | Block merge |
| Matrix parity | CI test (matrix) | Blocking | macOS and Linux both green | Block merge |
| Code review | PR | Blocking | 1+ approval | Block merge |
| CODEOWNERS | PR | Blocking | trait changes need maintainer review | Block merge |

## 4. Architecture Rule R1 Test (codifying §8.2 of architecture-design.md)

`crates/modeltap-core/tests/architecture.rs`:

```rust
//! Architecture rule R1: modeltap-core has no dependency on any plugin crate;
//! plugin crates do not depend on each other; modeltap-tui has no concrete plugin import.
//!
//! Implemented as a workspace-metadata test using `cargo metadata` JSON.

use std::collections::HashMap;
use std::process::Command;

#[derive(serde::Deserialize)]
struct Metadata {
    packages: Vec<Package>,
    workspace_members: Vec<String>,
}

#[derive(serde::Deserialize)]
struct Package {
    id: String,
    name: String,
    dependencies: Vec<Dep>,
}

#[derive(serde::Deserialize)]
struct Dep {
    name: String,
    kind: Option<String>,
}

fn workspace_metadata() -> Metadata {
    let out = Command::new(env!("CARGO"))
        .args(["metadata", "--format-version", "1", "--no-deps"])
        .output()
        .expect("cargo metadata");
    serde_json::from_slice(&out.stdout).expect("parse metadata")
}

fn deps_of<'a>(meta: &'a Metadata, name: &str) -> Vec<&'a str> {
    meta.packages
        .iter()
        .find(|p| p.name == name)
        .into_iter()
        .flat_map(|p| p.dependencies.iter())
        .filter(|d| d.kind.is_none()) // normal deps only
        .map(|d| d.name.as_str())
        .collect()
}

const PLUGIN_CRATES: &[&str] = &[
    "modeltap-plugin-ollama",
    "modeltap-plugin-llama-cli",
    "modeltap-plugin-hf",
    "modeltap-plugin-lm-studio",
];

#[test]
fn r1a_core_has_no_plugin_deps() {
    let meta = workspace_metadata();
    let core_deps = deps_of(&meta, "modeltap-core");
    for plugin in PLUGIN_CRATES {
        assert!(
            !core_deps.contains(plugin),
            "R1 violation: modeltap-core depends on plugin crate {plugin}"
        );
    }
}

#[test]
fn r1b_plugins_do_not_depend_on_each_other() {
    let meta = workspace_metadata();
    for plugin in PLUGIN_CRATES {
        let plugin_deps = deps_of(&meta, plugin);
        for other in PLUGIN_CRATES {
            if other == plugin { continue; }
            assert!(
                !plugin_deps.contains(other),
                "R1 violation: plugin {plugin} depends on plugin {other}"
            );
        }
    }
}

#[test]
fn r1c_tui_has_no_plugin_deps() {
    let meta = workspace_metadata();
    let tui_deps = deps_of(&meta, "modeltap-tui");
    for plugin in PLUGIN_CRATES {
        assert!(
            !tui_deps.contains(plugin),
            "R1 violation: modeltap-tui depends on plugin {plugin}"
        );
    }
}
```

This test runs as part of the `arch-rule` job. New plugin crates added in the future must be appended to `PLUGIN_CRATES` — flagged in CONTRIBUTING.md.

## 5. K3 Headless Benchmark — Design

Architecture-design §7 specifies: process start → first paint ≤ 150 ms target; full inventory ~1.15 s target. CI must verify this empirically.

### 5.1 Headless mode

`modeltap-app` accepts environment variables for benchmark mode:

- `MODELTAP_HEADLESS=1` — skip ratatui init; run discovery; emit timing JSON; exit 0. Equivalent to `--emit-timing` flag.
- `MODELTAP_FIXTURES=<path>` — use a fixture directory tree as the source of truth instead of real `~/.ollama` etc. Plugins respect this env via `DiscoveryCtx`.
- `MODELTAP_NO_HASH=1` — skip lazy SHA256 (already lazy by default; explicit for benchmarks).

Output JSON (stdout):

```json
{
  "schema": "modeltap.timing.v1",
  "process_start_to_first_paint_ms": 142,
  "first_paint_ms": 142,
  "first_paint_to_all_discovered_ms": 781,
  "all_discovered_to_indicators_ms": 187,
  "full_inventory_ms": 1110,
  "model_count": 47,
  "plugin_timings": {
    "ollama": 412,
    "llama-cli": 89,
    "hf": 781,
    "lm-studio": 156
  }
}
```

### 5.2 Fixture directory tree

`tests/fixtures/k3-bench/` contains a sized inventory representative of a real user (~50 models across 4 plugins):

```
tests/fixtures/k3-bench/
├── ollama/         # ~/.ollama/ shape: manifests + blobs (small placeholder files, real layout)
├── llama-cli/      # loose .gguf placeholders
├── hf/             # ~/.cache/huggingface/hub/ snapshot/blob shape
└── lm-studio/      # ~/.cache/lm-studio/models/ shape
```

Files are sparse (zero-bytes with set length, or 1 KB placeholders) — discovery walks the structure; it does not read content. SHA256 is lazy and not invoked in benchmark mode.

### 5.3 Thresholds (per outcome-kpis.md K3)

- Target: first paint < 1000 ms (warn if exceeded)
- Guardrail: first paint < 2000 ms (fail if exceeded)
- Full inventory: < 5000 ms (fail if exceeded; allows margin over 3 s NFR for CI runner variability)
- Per-plugin discovery: no per-plugin threshold in CI (varies by fixture); recorded for trend analysis only

CI runner is faster than typical user hardware in some respects (NVMe) and slower in others (shared cores). Targets are intentionally generous for guardrails to avoid false-positive flakes.

## 8. cargo-deny Configuration (`deny.toml`)

```toml
[advisories]
# Fail on RustSec advisories. Update db on every CI run via cargo-deny-action.
yanked = "deny"
ignore = []

[licenses]
# Only permissive licenses. Forbid GPL-family in dependencies.
allow = [
    "MIT",
    "Apache-2.0",
    "Apache-2.0 WITH LLVM-exception",
    "BSD-2-Clause",
    "BSD-3-Clause",
    "ISC",
    "Unicode-DFS-2016",
    "Zlib",
    "MPL-2.0",  # weak copyleft, file-level — acceptable for a dependency
    "CC0-1.0",
]
confidence-threshold = 0.9

[bans]
multiple-versions = "warn"
deny = []

[sources]
unknown-registry = "deny"
unknown-git = "deny"
allow-registry = ["https://github.com/rust-lang/crates.io-index"]
```

GPL-family is explicitly NOT in `allow` — `cargo deny check` fails the build if any dependency is GPL-licensed. Documented in CONTRIBUTING.md.

## 9. Optional Nightly Workflow (`.github/workflows/nightly.yml`)

Schedules `cargo-audit` against the RustSec advisory database. Files an issue automatically when a new advisory affects the project.

```yaml
name: nightly-audit
on:
  schedule:
    - cron: '0 6 * * *'  # 06:00 UTC daily
  workflow_dispatch:

jobs:
  audit:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: rustsec/audit-check@v2
        with:
          token: ${{ secrets.GITHUB_TOKEN }}
```

Optional for v1; recommended once dependency surface stabilizes.

## 10. Caching Strategy

- `Swatinem/rust-cache@v2` for `~/.cargo` and `target/`. Keys on Cargo.lock hash + OS.
- Restore-keys allow partial cache hits across PRs touching unrelated files.
- No manual cache management needed; the action handles invalidation.

Expected speedups (per Swatinem benchmarks): 3-5× on warm cache, ~2× on partial cache. Cold cache full CI run estimated at 8-12 min; warm at 3-5 min.

## 11. Local CI Reproduction

CONTRIBUTING.md instructs contributors to run the same checks locally:

```bash
# Install once
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
cargo install cargo-deny lefthook
lefthook install

# Run the same gates as CI
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings

```

A `Justfile` (or `make ci-local` target) is recommended to bundle these into one command. DELIVER decides whether to ship the Justfile in v1 or defer.

## 12. Failure Modes and Owner Routing

| Failure | Likely cause | First responder | Action |
|---|---|---|---|
| fmt fails | Forgotten `cargo fmt` | PR author | Run `cargo fmt --all`, push |
| clippy fails | New warning introduced | PR author | Fix or `#[allow]` with justification |
| test fails on macOS only | Platform-specific assumption (paths, lsof) | PR author | Fix; add cross-platform abstraction in `modeltap-core` |
| arch-rule R1 fails | Forbidden cross-crate import | PR author | Move logic to `modeltap-core`; remove plugin-to-plugin or core-to-plugin dep |
| cargo-deny fails (license) | New dep with disallowed license | PR author | Replace dep or seek maintainer exception |
| cargo-deny fails (advisory) | Upstream vuln | Maintainer | Bump dep; if no fix available, evaluate ignore + tracking issue |
| K3 bench > 2 s | Discovery regression | PR author | Profile; revert the regression; or document and request guardrail bump (rare) |
| Matrix only Linux green | macOS-specific bug | PR author | Reproduce on macOS, fix |
